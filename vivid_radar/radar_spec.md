## 2. Module A1 : 레퍼런스 채널 스카우트 모듈 (ChannelScout)

- **목표**: 특정 키워드 검색 시 상단에 노출되는 채널 중, 실력이 검증된 A급 레퍼런스 채널 발굴.
- **작동 및 필터링 워크플로우 (순차 적용 필수)**:

1.  **키워드 검색**: 타겟 주제(예: 이란전쟁) 검색 후 노출되는 채널 주소 수집.
2.  **AI 라벨 전수 조사 (0순위 필터)**: 채널의 최근 롱폼 영상 3~5개를 무작위 클릭하여 '변경되었거나 합성된 콘텐츠' 라벨 존재 여부 확인. 하나라도 누락 시 즉시 탈락 처리 및 연산 중단.
3.  **구독자 기준**: 채널 홈의 subscriber_count 추출. 내 채널 구독자 수의 10배 미만이어야 하며, 신규 채널 보호를 위해 하한선 공식을 적용함: `max(구독자*10, 5000)` (5000값은 사용자가 설정 가능하도록 UI 설계).
4.  **활동성 검증**: '동영상' 탭 기준, 최근 4개 영상의 업로드 날짜가 모두 '7일 이내'인지 확인(최근 'n'개 값은 사용자가 설정 가능하도록 UI 설계).
5.  **실력 검증**: (최근 10개 영상 평균 조회수 / 채널 구독자 수) >= 3 인지 확인 (기준치'3'은 사용자가 설정 가능하도록 UI 설계).
6.  **결과물**: 위 조건을 모두 통과한 채널 최소 3개 이상 SQLite 적재 (성과 지표순 정렬) (최소 n개 값은 사용자가 설정 가능하도록 UI 설계).

## 3. Module A2 : 핫한 주제 탐색 모듈 (TopicDiscovery)

1. **방식 A (구독 채널 탐색)**: 내가 구독한 채널 중 최근 1주일 내 업로드된 영상 탐색.
2. **방식 B (메인 피드 탐색)**:
   - 시크릿 창이 아닌, 기존 크롬 브라우저의 사용자 프로필 데이터(User Data Directory)를 Playwright에 연동하여 로그인된 세션으로 유튜브 알고리즘 기반 메인 피드를 탐색.
3. **지표 계산 및 필터 (vidiq 방식 직접 연산)**:
   - **VPH**: (현재 조회수 / 업로드 후 경과 시간(h)) 직접 계산. VPH > 100 이상 필터 (기준치'100'은 사용자가 설정 가능하도록 UI 설계).
   - **Outlier**: (현재 영상 조회수 / 해당 채널 최근 30일 평균 조회수) 직접 계산. Outlier >= 2.0 이상 필터 (기준치'2.0'은 사용자가 설정 가능하도록 UI 설계).
   - **델타(Delta) 연산**: 이전 스케줄러 실행 시간에 SQLite에 기록된 조회수와 현재 조회수의 차이를 계산하여 실시간 화력(dVPH) 측정.
   - 내 채널 구독자 수의 10배 미만 채널로 한정 '공식 : max(구독자\*10, 5000)' (방식 B의 경우).
4. **최종 검증**: 위 조건을 통과한 영상의 제목을 시크릿 창에서 검색하여, '관련 동영상' 구분선 이전에 'AI 라벨'이 붙은 영상이 3개 이상 노출되면 오늘의 핵심 주제로 최종 선정.
5. **결과물**: 오늘의 핵심 주제로 선정된 주제 최소 3개 이상 출력(VPH 기준 정렬, Outlier, dVPH도 표기)

## 4. Module A3 : 노출 최적화 제목 탐색 모듈 (FindTitle)

- **하이브리드 워크플로우**:
  1.  Gemini API: 핵심 키워드 조합 5가지 전략 수립.
  2.  Gemma 4 (Local e4b): 키워드 기반으로 100개의 제목 변형본 대량 생성.
  3.  Playwright: 시크릿 모드로 유튜브 검색 자동 검증.
- **Playwright 검색 검증 방식**:
  - **등급별 배치 검색 (Batching)**: 100개를 15개씩 묶어 등급(A~G) 부여. A등급부터 우선 검색.
  - **안티봇 Jitter 적용**: 각 제목 검색 사이 2~7초 사이의 무작위 대기 시간 부여.
  - **URL 파라미터 직접 타격**: 필터 클릭 과정을 생략하고 검색 URL 뒤에 `&sp=CAASBBABGAE%253D` (동영상+이번주+관련도순) 파라미터를 붙여 즉시 접속.
  - **조기 중단 (Short-circuiting)**: '관련 동영상' 섹션 감지 시 하단 데이터 읽기 즉시 종료. A등급 검색만으로 충분한 후보가 나오면 나머지 등급 검색 취소.
  - **리소스 차단**: Playwright `route` 기능을 사용하여 이미지, 폰트, CSS, 광고 스크립트 다운로드를 0초 원천 차단하여 텍스트(HTML)만 로딩.
  - **결과**: AI 라벨 영상이 많이 노출된 순으로 1~5순위 제목을 출력 및 DB 적재. Headless/Headful 토글 옵션 필수 구현.

## 5. Handover & Style Guide (Claude 호환성)

기존 VIVID 시스템은 다른 AI(Claude)에 의해 작성되었습니다. 이질감 없는 통합을 위해 다음 코딩 스타일을 엄수하십시오.

1. **로깅 및 상태 출력**: `print()` 대신 기존 코드의 `StatusLogger` 클래스 스타일과 호환되도록, 엔진단에서는 `logging` 모듈을 사용하되 추후 GUI에서 쉽게 가로챌 수 있도록 커스텀 Logger 구조(또는 yield 기반 제너레이터)로 이벤트를 방출(Emit)하십시오.
2. **네이밍 컨벤션**: 클래스 내부의 프라이빗 변수와 메서드는 반드시 언더바(`_`)로 시작하십시오 (예: `def _calculate_vph():`).
3. **타입 힌팅**: 파이썬 3.10+ 최신 타입 힌팅(`Path | None`, `list[dict]`)을 적극 사용하십시오.
