운영 매뉴얼: 신규 캐릭터/소품 등재 절차
1. 폴더 구조 (현재 미존재 → 처음 등재할 때 직접 생성)

c:\Youtube\Vivid_Workspace\
├── assets\
│   └── references\          ← 여기에 PNG 원본 저장 (Gold Standard)
│       ├── char_<key>_front.png
│       ├── char_<key>_side.png
│       ├── char_<key>_back.png
│       └── prop_<key>.png
└── shared_assets\
    └── references_catalog.json  ← 메타데이터만 등재
assets/references/ 폴더는 아직 없어. 첫 등재 때 만들면 돼.

⚠️ Git 추적 정책: 레퍼런스 PNG는 보통 수MB~수십MB라 .gitignore에 assets/references/*.png 추가 권장. 카탈로그 JSON은 추적, 이미지는 로컬/별도 백업.

2. PNG 원본 규격 (ComfyUI FaceID/IP-Adapter 정합성)
항목	권장값	이유
해상도	1024×1024 정사각형	FaceID/IP-Adapter 입력 표준
배경	단색 흰색 또는 투명 PNG	매팅 노이즈 최소화
캐릭터 비율	얼굴이 프레임의 30~50%	FaceID 임베딩 안정
스타일	최종 영상과 동일 톤 (noir webtoon)	LoRA와 충돌 방지
파일명	소문자 + 언더스코어, 영문만	n8n/ComfyUI 경로 안전
캐릭터는 같은 인물의 front/side/back 3장을 같은 의상·같은 헤어스타일로 일관되게 그려야 LLM이 변형 없이 합성함.

3. 카탈로그 업데이트 — 캐릭터 추가 예시
shared_assets/references_catalog.json을 열고:

Step 1: characters._template을 복사해서 신규 키로 추가

"characters": {
  "_template": { ... 그대로 유지 ... },

  "expert_park": {
    "display_name": "박 교수",
    "appearance_anchor": "A 50-something Korean male economics professor, wearing a beige cardigan over a white shirt, round wire-frame glasses, slightly graying hair parted to the side, thoughtful expression",
    "default_lora": "noir_webtoon_style",
    "faceid_weight": 0.85,
    "style_weight": 0.65,
    "variants": {
      "front": {
        "ref_image_id": "char_expert_park_front",
        "file_path": "assets/references/char_expert_park_front.png",
        "usage_hint": "강의/해설 정면 컷"
      },
      "side": {
        "ref_image_id": "char_expert_park_side",
        "file_path": "assets/references/char_expert_park_side.png",
        "usage_hint": "걷거나 칠판을 가리키는 측면 컷"
      },
      "back": {
        "ref_image_id": "char_expert_park_back",
        "file_path": "assets/references/char_expert_park_back.png",
        "usage_hint": "데이터 모니터를 응시하는 뒷모습"
      }
    }
  }
}
Step 2: 필수 체크리스트
 appearance_anchor는 영문으로 작성 (FLUX 입력이 영문). Node 4 프롬프트 앞단에 그대로 붙음.
 ref_image_id는 반드시 char_<key>_<angle> 패턴 준수. Node 4가 이 ID로 매핑.
 file_path의 실제 PNG가 assets/references/에 존재해야 함. Node 7의 'File Exists' 검사가 1차 검증.
 3각도(front/side/back) 중 일부만 보유한 경우, 확보한 variant만 등재. Node 4가 없는 각도를 요청하면 fallback 발동(아래 7번 참조).
 faceid_weight 0.60.95, style_weight 0.50.85 범위 준수 (validation_rules 강제).
4. 카탈로그 업데이트 — 소품 추가 예시

"props": {
  "_template": { ... 그대로 유지 ... },

  "stock_chart_red": {
    "display_name": "급락 주가 차트",
    "description": "A digital stock chart screen showing a sharp downward red candle pattern, glowing red against a dark background, journalistic webtoon line art",
    "ref_image_id": "prop_stock_chart_red",
    "file_path": "assets/references/prop_stock_chart_red.png",
    "denoise_strength": 0.5,
    "default_lora": "noir_webtoon_style",
    "style_weight": 0.65,
    "usage_hint": "위기/하락 맥락 / 경고 강조 컷"
  }
}
denoise_strength는 원본 보존 강도 — 0.3(거의 그대로) ~ 0.7(많이 변형) 사이에서 조절. 명세상 기본 0.5.

5. 메타데이터 갱신
파일 상단 last_updated 필드를 등재일로 수정:


"last_updated": "2026-04-29",
(파이프라인 자동 갱신 아님 — 수동.)

6. 등재 후 검증 (1회)
신규 등재 직후 Node 7만 단독 실행해 dry-run 권장:

ComfyUI에 LoadImage가 정상 로드되는지
FaceID/IP-Adapter가 weight 적용되는지
캐시 키(SHA1) 생성 후 asset_cache/<hash>.png에 저장되는지
검증 통과하면 정식 운영 투입.

7. 카탈로그에 없는 캐릭터/소품이 등장할 때
Node 4가 자동으로 ref_image_id: "none"을 부여 → Node 7이 FaceID/IP-Adapter Bypass + Pure Text-to-Image로 폴백. 카탈로그를 미리 다 채울 필요 없음. 자주 재등장하는 인물·소품만 골라서 등재하면 됨.

8. 운영 팁
네이밍 컨벤션 일관성: expert_park, anchor_kim처럼 <역할>_<성> 형식 추천 (검색·관리 편의).
신규 등재 vs 변형: 같은 인물이 의상만 바뀌면 새 캐릭터로 만들지 말고 appearance_anchor만 다음 영상 제작 직전에 수정. 인물 정체성이 흔들리면 안 됨.
이미지 백업: assets/references/는 Git 추적 안 하므로 NAS/외장하드 별도 백업 필수. 분실 시 영상 시리즈 일관성 깨짐.
카탈로그 변경 후: 다음 파이프라인 실행이 자동으로 새 항목 인식. 캐시는 (ref_image_id + seed + prompt) 조합 기준이라, 신규 등재 후 첫 사용은 캐시 미스 → ComfyUI 1회 호출 발생.
지금 들어있는 anchor_kim / shoes_brown_leather / newspaper_economic은 그대로 둬도 무방(빈 카탈로그 시작이면 Node 4·7이 동작 검증을 못 해서 첫 실행 위험). 운영 들어가기 전에 실제 등재할 캐릭터/소품으로 교체하면 됨. 원하면 지금 비우고 깡통 상태로 둘 수도 있어.
